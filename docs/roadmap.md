# S2U 开发路线（V1.1 → V2.0）

此路线为拟定计划，不代表对应版本已经发布。项目保持 Vue 3 + Vite、纯前端、GitHub Gist 可选同步、原版玻璃主题和原有三页工作区。旧分享链接、历史记录、收藏、标签、图标和设置继续兼容。禁止静默扩大 Token 权限、自动上传原本未选择同步的数据或未经确认覆盖本地数据。

## 阶段与验收

| 阶段 | 重点 | 验收条件 |
| --- | --- | --- |
| V1.1 | 收尾遗留 PR、部署和稳定性 | 最新 master 完整 CI 与 Pages 部署；Netlify/真实设备另行核验；过期 PR 有明确处置 |
| V1.2 | UI Foundation 与动效 | 主导航、创建/历史/收藏输入与操作按钮、云同步/编辑/二维码/快捷启动弹窗复用基础组件；320px 与深浅主题对齐；快速反向切换、键盘焦点、减少动态效果回归 |
| V1.3 | Gist 可靠性 | 有共同基线的独立收藏变更自动合并，冲突预览；本地和远端备份可校验恢复；跨账号迁移显式确认；同步失败保留待同步数据 |
| V1.4 | 链接工作台管理 | 收藏拖拽与键盘排序、标签与筛选、历史转收藏、统一图标、命令搜索；不增加无必要一级导航 |
| V1.5 | 链接模板 | Obsidian、VS Code、普通网页参数编辑与批量生成；使用统一 linkCodec；不自动启动外部应用 |
| V1.6 | 架构与性能 | 分离 Change.vue 的同步协调、跳转控制、命令快捷键、数据导入导出；按需加载；分级 CI 和构建预算；存储迁移可回退 |
| V2.0 | 发布验收 | 完整安全、数据兼容、浏览器及设备验证；版本说明、迁移说明、部署及回滚流程 |

## 实施顺序

1. 收尾通过测试且无冲突的现有 PR；不重复合并已替代变更。
2. 收藏独立修改合并与冲突安全校验，然后完成恢复预览、备份格式和迁移安全测试。
3. 将剩余原生控件与弹窗逐步迁移至共享基础组件；保留 DOM 语义和现有快捷键。
4. 在稳定数据模型上实现收藏管理、搜索、模板等功能，按实际需求减少装饰和层级。
5. 逐步拆分业务协调模块；发布前完整回归并记录体积、部署和真实设备验证结果。

## 合并与发布

每个 PR 聚焦一个问题，中文提交；必要测试通过、无合并冲突、无未解决审查线程才允许 squash merge。数据、协议、认证、存储与依赖修改执行完整回归；纯样式与文档的快速检查以分级 CI 正式合并为前提。未验证内容不得标记完成，外部应用启动和真实账号同步需人工验收。禁止强制合并失败 PR。
